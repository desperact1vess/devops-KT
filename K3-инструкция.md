# Как завершить и сдать КТ3

Студент: Nikita. Папка содержит локальный Git-репозиторий с веткой `kt3` и подготовленными последовательными версиями. Публикация и реальные Actions намеренно не выполнялись. Если загрузить на GitHub только конечные файлы, промежуточные запуски с ошибками не появятся; для них нужно отправить подготовленные коммиты по очереди.

1. Откройте терминал в этой папке. Убедитесь, что `origin` указывает на `https://github.com/desperact1vess/devops-KT.git`: `git remote -v`. Убедитесь в настройках репозитория, что Actions разрешены. Не отправляйте файлы с личными данными или секретами.
2. Последовательно выполняйте команды ниже. После **каждой** откройте GitHub → Actions → Student CI, дождитесь результата и запишите ссылку, событие `push`, SHA и нужные строки лога. Не запускайте все команды разом: иначе не будет времени изучить каждый результат. Если run не соответствует ожидаемому, остановитесь и разберите ошибку, прежде чем продолжать. Команды отправляют существующие коммиты в ветку `kt3`, не изменяя `main`.

| Команда отправки | Что проверить (ожидаемый результат) |
|---|---|
| `git push origin 7e61488363ebddc6b99c7315d0cb8e5dda9728fc:refs/heads/kt3` | K3-02: исходный Student CI; runner, checkout, setup-python, `python --version`. |
| `git push origin 4d7c7d8a6d4cbd10fbd2dc73e88dcd011a4a202d:refs/heads/kt3` | K3-03: успешное выполнение реальных тестов. |
| `git push origin 2db4f1b05bacd016d741eca5eea38b14fc83d0f5:refs/heads/kt3` | K3-03: failed test; сохранить assertion из лога. |
| `git push origin d5baee9706afc3e9fdcf94b98a1956c07e481830:refs/heads/kt3` | K3-03: исправленный успешный test. |
| `git push origin 779e49512c1c47512b3f0e6ee1e079cb869966ff:refs/heads/kt3` | K3-04: тест и сборка проходят. |
| `git push origin a295ba246577b1ff55ae7aa9087107d6f3631786:refs/heads/kt3` | K3-04: test failed, build skipped. |
| `git push origin 868de76f072d99523cf2696da839f6be5367a682:refs/heads/kt3` | K3-04: успешные test и build в одном run; сохранить команду и лог сборки. |
| `git push origin d97ef71bdb509d1fc6c27d0e82607cc75d833195:refs/heads/kt3` | K3-05: test успешен, build failed; записать первое содержательное сообщение о Dockerfile. |
| `git push origin 019b7a9707b7d30ab1756d984ac9497158c12560:refs/heads/kt3` | K3-05: исправленные test и build. |
| `git push origin HEAD:refs/heads/kt3` | Отправить итоговые отчёты, инструкцию и метку Nikita; проверить финальный run. |

3. Впишите фактические ссылки, события, SHA, статусы и строки логов в соответствующие файлы `evidence/K3-02.md` — `K3-05.md`; уберите отметки о неподтверждённых результатах только после проверки. Добавьте и отправьте коммит с отчётами: `git add evidence && git commit -m "Complete KT3 run evidence" && git push origin HEAD:refs/heads/kt3`. Этот коммит создаст ещё один run; ссылки в отчётах должны указывать на уже изученные runs.
4. Создайте PR из `kt3` в `main` **своего** репозитория. В PR проверьте файлы, ссылки и результаты; дайте преподавателю ссылку, не сливая PR до проверки. Для события `pull_request` SHA проверяемого результата слияния может отличаться от SHA ветки, поэтому записывайте SHA, указанный в конкретном run.

Если загрузить файлы через браузер без Git-истории, потребуется вручную повторить все промежуточные изменения отдельными коммитами и ждать каждый запуск. Для сохранения уже подготовленных промежуточных версий удобнее приведённые команды Git.
