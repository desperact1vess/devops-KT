# K3-04. Сборка после тестов

Студент: Nikita.

Отдельный job `build` на `ubuntu-latest` зависит от `test` через `needs: test`, заново получает исходники тем же checkout SHA, что и шаблон, и выполняет:

```sh
docker build -f lab/Dockerfile -t devops-student:${{ github.sha }} lab
```

Тег связывает образ с SHA текущего run; при `pull_request` это может быть SHA проверяемого результата слияния. При ошибке `test` зависимый `build` должен получить `skipped`. Образ не отправляется в registry и исчезает вместе с временным runner.

Подготовлены коммиты: добавление сборки — `779e49512c1c47512b3f0e6ee1e079cb869966ff`; ошибочное ожидание — `a295ba246577b1ff55ae7aa9087107d6f3631786`; восстановление — `868de76f072d99523cf2696da839f6be5367a682`.

**Ещё требуется подтверждение:** ссылки, события и SHA run с `failed test` / `skipped build` и исправленного успешного run; строка реальной сборки из журнала. Docker локально не найден, сборка не проверена.
