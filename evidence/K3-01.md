# K3-01. CI/CD и ветки

```text
короткая ветка kt3 → push → PR в main своей копии
                              ↓
                    Student CI: тест → сборка
                              ↓
                    проверка и решение о слиянии → main
```

Push и pull request запускают Student CI. Интеграционный тест проверяет создание заявки через web и API, в том числе ответ HTTP 201 и сохранённую запись. После успешных тестов собирается Docker-образ. Ошибка теста возвращается в интерфейсе Actions и проверках PR ещё до слияния; если тесты проходят, ошибка сборки видна на этапе сборки.

**CI** — частое объединение изменений с автоматическими проверками. **Continuous delivery** готовит проверенное изменение к выпуску, а решение о выпуске принимается отдельно. **Continuous deployment** автоматически развёртывает прошедшее проверки изменение. Сборка образа сама по себе не развёртывает приложение; данный workflow также не публикует образ в registry.

Git-flow использует дополнительные долгоживущие ветки, например develop и release, а также ветки исправлений. Для небольшой учебной работы короткой ветки и PR достаточно: проще проверять изменения и быстрее получать обратную связь, не управляя дополнительными ветками.

Источник приложения, тестов и шаблонов: [DevOps-course](https://github.com/mdvwork/DevOps-course). Помощь в подготовке работы: Claude. В исходном репозитории работы-допуска приложение и Dockerfile предыдущего этапа отсутствовали; приложение и тесты взяты из курса, Dockerfile подготовлен по его bootstrap-образцу. Выполнение КТ2 этим не подтверждается.
