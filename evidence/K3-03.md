# K3-03. Тестовый барьер

Студент: Nikita.

Команда `python -m unittest discover -s tests -p test_app.py -v` запускает интеграционные тесты приложения. `test_create_request` проверяет, что отправка заявки возвращает HTTP 201 и запись сохраняется. В эксперименте изменяется ожидание теста на 200, а не поведение приложения; поэтому несоответствие должно привести к ошибке assertion и ненулевому коду выхода.

Подготовлены коммиты: тесты добавлены — `4d7c7d8a6d4cbd10fbd2dc73e88dcd011a4a202d`; неверное ожидание — `2db4f1b05bacd016d741eca5eea38b14fc83d0f5`; исправление — `d5baee9706afc3e9fdcf94b98a1956c07e481830`. В итоговом файле ожидается 201.

**Ещё требуется подтверждение в GitHub Actions:** ссылки, события и SHA неуспешного и исправленного run, а также точная строка assertion из журнала. Предполагаемый результат не является фактическим логом. Локальный запуск тестов был отклонён автоматической проверкой разрешений.
